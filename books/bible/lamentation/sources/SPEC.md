# 耶利米哀歌研讀 — 章節撰寫規格（給每位撰寫者；2026-10-30）

先讀：`sources/PLAN.md`（事實、骨幹、十章、來源）、本檔、範例章 `01-how-lonely-sits-the-city.md`（**完整讀一遍，照它的體例**）。
體例＝約翰福音 11 節章節模板（`.claude/skills/eat-bible/references/chapter-template.md`）。你只寫**分到的章**，不改其他檔、不改範例章、**不 git add／commit**（倉庫有其他 session 同時在改檔）。

## 一、檔案骨架（11 個 `## `，順序固定，與範例章逐項同構）

用 `python3 books/bible/lamentation/sources/new_chapter.py NN` 先產生骨架：它會建立章檔，YAML、H1、參照行、`經文核對`、11 個 `##` 標題與 `<!-- TODO:… -->` 記號，經文區塊已由腳本逐字展開（**你不手打任何經文區塊**）。然後一節一節用 Edit 把 TODO 換成內容，**不要一次寫整檔**。
11 節順序：基督焦點 · 配詩 · 經文 · 背景 · 原文研讀 · 領受要點 · 歷代注疏 · 詩篇與聖詩 · 老弟兄查經 · 生命應用 · 與其他經文的關聯；末尾一行斜體 `*本章研讀整合…*`。`---` 前後必須有空行（否則被 pandoc 吞成 Setext 標題）。H1 不加真實章節範圍。

## 二、基督焦點（必備）

`> **本章鑰詞：<原文> 「中譯」（出處）** \` + `> **全書座標**：啟示的次序·第 N 步——…` ＋ 一至兩段 hook。座標句要說出**這章在全書骨幹上的位置與作用**，不可只複述章節大意，不可與別章雷同。啟示的次序五步與用詞見 PLAN.md §二（照抄步名）。

貫穿全書的線（用得上就點出，不要硬塞）：**神不開口**（全書無「耶和華說」，唯一的神的話是 3:57 被回憶出來的）；**「安慰者」空著五次**（1:2, 9, 16, 17, 21）；**「求你看」「求你記念」**（1:9, 11, 20；2:20；5:1）；**字母詩**（哭泣有次序：א 到 ת）；**主是動詞的主語**（2:1–8, 17）。

## 三、不可越過的線（違反即退件）

1. **經文**：正文中任何「」＋（出處）的經文引句，必須逐字出自 `sources/scripture/cuv.tsv`（哀歌）或 `python3 books/bible/lamentation/sources/scripture/cuv_lookup.py <書縮寫> <章> <節>`（他書，和合本 FHL，書縮寫如 耶、賽、太、啟）。**引句裏不可插括號譯注**；引句與出處節號必須對得上。**寫完跑**：`python3 scripts/verify-prose-citations.py books/bible/lamentation --self 哀`（0 MISS 才算過；若腳本不認得某書縮寫，把該句改成不加引號的轉述並註明）。
2. **注疏引文**：只用已下載來源，**沒有可定位原文就不加引號**。可用：亨利 `sources/commentary/henry-lam.txt`（`ii`＝哀1，`iii`＝哀2，`iv`＝哀3，`v`＝哀4，`vi`＝哀5）；加爾文 `sources/commentary/calvin/lamentations.txt`（只引加爾文本人的句子，不引 `— Ed.`）；教父 `sources/fathers/INDEX.md`、司布真 `sources/spurgeon/INDEX.md`（只引 INDEX 已列的逐字句；某章沒有可用條目就不立該節）。合併語料 `sources/commentary/corpus.txt`（亨利＋加爾文）。**摩根、麥克阿瑟不立專節**（PLAN §五）。引文格式與範例章逐字相同：`> "English quote"` 換行 `> — 作者, *書名*, 章節 (來源)`；引文前一段中文導讀是撮述不是翻譯，必須誠實反映作者**實際在做甚麼**（例如「用作基督論的證詞，不是逐節解經」）。**寫完跑**：`python3 scripts/verify-citations.py books/bible/lamentation --source books/bible/lamentation/sources/commentary/corpus.txt`（OK／DRIFT／MISS 都要看；教父、司布真條目另核其原檔）。
   - 加爾文英譯本內有編者按語（`— Ed.`）；亨利文本含網頁雜訊，引文只取正文句子。
   - 注疏引文最常見三類錯：查無此句／立場說反／推論相左。不確定就不加引號。
3. **不杜撰老弟兄的話**：倉庫沒有哀歌的老弟兄第一手材料。「老弟兄查經」一節只用他的**方法**（提問、全經連線、落到每日祭壇、回到耶穌），**不加引號歸給他任何話**。稱呼一律「老弟兄」，不寫「黃長老」。
4. **不編史料**：年代、人名、地名、數字，只用經文與已下載注疏支持的；推測要寫明「推測」。**全稱斷言（「全書只有」「每一次」「從不」）必須先用程式數過**（`sources/scripture/cuv.tsv`、`sources/hebrew/heb.py`）。字頻報數字時註明依據與計法（和合本中文字面？希伯來字根？）。作者問題：書卷無署名，傳統歸耶利米；寫「傳統上歸給耶利米」，不寫成定論。
5. **原文研讀**：希伯來詞形一律用 `python3 books/bible/lamentation/sources/hebrew/heb.py <章> <節,節>` 輸出**複製**，不憑記憶打 niqqud；希伯來字在中文行文裏前後各留一個空格；表格欄寬照範例章。不確定的詞義，寫「字面是…」並指出出處（亨利／加爾文／已下載來源），不要靠記憶斷言詞源。
6. **不硬說預表**：必須有經文本身的連結才可說（見 PLAN §二「基督的線」）；其餘只寫「本書的對照，經文沒有互相引用」。**不抹平張力**：3:8 與 3:44（禱告被擋住）對 3:55–57（你聽見了）、2:17 神的作為與 3:33（不甘心使人受苦）、3:64–66 的報應祈求、4:10 的人吃人（敘述性，不當成教導）、4:22 與 5:22 的語氣落差——都讓它們保持張力。
7. **版本**：經文塊只由腳本產生；散文中的經文引句用和合本（CUV，FHL 版，字形用「裏／甚麼／那裏」），英文詞若引 NASB 1995 須與 `nasb1995.tsv` 逐字相同。和合本三處只留字母 `a` 的併節問題**不存在於哀歌**（已查）。
8. **不可有**：空洞屬靈套話、AI 腔、emoji、「值得注意的是」這類墊字、同一點在同章講三次以上。「活在今天」不編造 AI／時事案例；寫不出真實觸點就寫具體的生活處境。不可把苦難「合理化」成安慰話——哀歌的誠實就是不快快安慰。
9. **性與暴力**：哀歌有婦人吃嬰孩（2:20；4:10）、被擄的婦女與處女受凌辱（5:11–13）的描寫；如實寫經文所寫，不渲染、不評論得像是在辯護。

## 四、章節內容規格

- 長度：每章 18–26 KB（含經文區塊；經文區塊由腳本展開，你寫的部分約 9–13 KB）。哀歌單元較短（10–22 節），寧可寫得實、不要灌水。
- 背景 2–3 個 `###`；原文研讀 5–8 列（每列都能用資料核對）；領受要點 **3–4 條**，各自只屬於本章（搬到別章會不通順才算數）；
- 歷代注疏：`### 教父時期`（有可用條目才立）／`### 改革宗時期 (加爾文)`／`### 清教徒 (亨利)`／`### 司布真`——有哪個立哪個，每節 1–3 條逐字引文；體例說明框照範例章（並寫明本卷不立摩根與麥克阿瑟）。
- 詩篇與聖詩：一至二篇詩篇（逐字 CUV 引句）＋「配詩（見上）」一段說明。可用的詩篇對讀：詩74、79、88、130、137；詩30:5；詩22:7；詩102（用得上就用）。
- 老弟兄查經：`**精義一句話**`（一句，記得住）→ `### 全經連線`（3–5 條，每條出處對得上、引句逐字）→ `### 提問式對話`（先問／再問／追問／落到自己）→ `### 活在今天` → `### 今天的祭壇`（早晨／晚上／一個行動）→ **`**你看見耶穌了嗎**？`** 一段收尾（只用有經文連結的線）；
- 生命應用：默想問題 ≤3（角度不與提問式對話重複）＋禱告回應（奉主耶穌基督的名，阿們；禱告可帶哀歌式的誠實，不必快快轉成頌讚）；
- 與其他經文的關聯：表格 8–12 列；
- **配詩**：用 `sources/hymns/NN-*.txt`（NN＝本書章序）。把英文兩節逐字抄入（含該檔標頭給的作者與年份；年份欄寫「not stated on source page」的，出處行只寫作者名），自己寫繁體中文意譯（逐行對照），版式與範例章相同。若該檔有 NOTE，在回報中註明，不要默默改歌詞。**配詩的「說明句」必須誠實**：不可說經文與聖詩互相引用；不可把聖詩裏沒有的意思寫進去。**本輪你不寫配詩**：`## 配詩` 的 `<!-- TODO:配詩 -->` 與詩篇與聖詩節裏的「### 配詩（見上）」段，一律保留 `<!-- HYMN-PENDING -->` 記號（主線稍後統一補）；回報時說明即可。
- 全章（除上述配詩記號外）不得出現：`TODO`、`@@`、`需verify`、`待補`；書稿行文不得出現工具與內部檔名（`.tsv`、`heb.py`、`corpus.txt`）與第一人稱過程語。

## 五、寫作流程（避免停滯）

1. 讀範例章與本檔；讀你章節範圍的 `cuv.tsv` 行、`python3 sources/hebrew/heb.py`、亨利／加爾文相關段落、`fathers/INDEX.md`、`spurgeon/INDEX.md` 對應列。
2. **分段寫入**：`new_chapter.py` 產生骨架後，**一個 TODO 一個 TODO 地用 Edit 換**，前半（到「領受要點」）先完成，再寫後半。**不要一次寫整檔**。
3. 跑：`python3 scripts/lint-chapter-markup.py <章檔>`、`python3 scripts/check-prose-scripture-quotes.py <章檔>`、`python3 scripts/verify-prose-citations.py books/bible/lamentation --self 哀`、`python3 scripts/verify-citations.py books/bible/lamentation --source books/bible/lamentation/sources/commentary/corpus.txt`。全部乾淨才回報。
4. 回報（≤300 字）：檔名、大小、11 節核對、各檢查結果、**你不確定／可能有誤的地方清單**（尤其詞義、字頻、史實、歸屬）。誠實：做不到的標明，不要含糊帶過。

## 七、已知不可踩的坑（來自全庫歷史）

- 檢查器曾抓出：引句內插括號、節號標錯、引文歸屬錯置——**人眼讀不出、檢查器才抓得到**，所以一定要跑腳本。
- 注疏引文最常見的三類錯：查無此句／立場說反／推論相左。不確定就不加引號。
- 配詩說明、書卷結語最容易「說得比來源多」。
- 同章同一個點只講一次；默想問題不要與「提問式對話」重複。
- 專有名詞：和合本譯名（尼布甲尼撒、西底家、以東、拿細耳……）一律照 `cuv.tsv`。
- 規格裏的「頭條斷言」會原樣傳到各章：凡「全書只有」「唯一」類斷言，各自重數一次，而且數字報告的算法要註明。
