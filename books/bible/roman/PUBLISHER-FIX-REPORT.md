Confirmed by embedded-font census: exactly the 15 pages patched by `put()`/`replace()` (1, 6, 8, 9, 10, 27, 30, 48, 152, 154, 244, 259, 331, 333, 348) plus the front/back covers carried the fallback fonts; all other pages already used the correct font. Embedded-font census after the fix: zero occurrences of Droid Sans Fallback or Charis SIL anywhere in the 348 pages. Side effect confirming the prior bug was real, not merely cosmetic: the reader-guide page's chapter-link count dropped from 48 to the correct 16 (one per chapter) — the fallback font's wider CJK metrics had been reflowing the chapter table and producing duplicate `search_for` matches. The build's own self-verification (pixel-identity outside approved regions, link resolution, page geometry, metadata) passed; 13 regression tests and `check_book.py`/`lint-scripture-text.py` re-run clean. **2026-09-24 from-source re-layout, pages 229-end**: an editorial addition to chapter 12's 背景 section (a doctrine-to-ethic table tying 12:1-2 back to chapters 1-11) needed ~330pt of vertical space against ~16.7pt of actual slack on the frozen page — too large to patch in without reflowing the rest of the book. After explicit two-round user confirmation of the scope (this reverses part of the 2026-09-21 baseline-preservation decision), pages 1-228 (front matter + chapters 1-11) stay the pixel-frozen original baseline; chapter 12 onward (chapters 12-16 + all back matter: part dividers, appendices, colophon, afterword) is now a fresh xelatex/pandoc render of the current markdown sources through `templates/pdf/romans.latex`, rebuilt on every `make pdf` run (`scripts/build_fresh_pdf.py`) and spliced onto the frozen front by `scripts/merge_baseline_pdf.py`. Real, previously-undiscovered bugs fixed to get this pipeline working at all (it was dead code before — `build_book.py`'s `pdf` target short-circuited straight to the old merge path and had never actually been run through xelatex):
- Front matter/part-divider files weren't marked `{.unnumbered}`, so they silently consumed `\chapter` numbers (the exact defect eat-bible's gotchas.md documents generally).
- A markdown-source regex wrapped Greek runs in a bare `{\greekfallback ...}` group targeting a command that only existed in the old, now-unused `templates/roman-header.tex` — doubly broken (undefined command, and bare braces get escaped by pandoc's reader regardless). Removed outright: the real template already auto-switches Greek fonts via ucharclasses.
- Two part-divider pages ("卷末 · 望向那一頭", "附錄") have no corresponding markdown source file at all (they predate the current 26-file manifest) — reproduced verbatim from the baseline PDF rather than silently dropped.
- Printed page-number continuity across the splice seam, handled via a `\setcounter{page}{209}` raw-LaTeX injection right before the chapter-12 heading rather than patching ~117 footer numbers by hand.
- PyMuPDF's `insert_pdf()` silently drops pandoc/hyperref's named-destination links (`chapter.N`) when the target is a brand-new empty document — zero errors, zero warnings, just no working links. Fixed by splicing the frozen front INTO the live fresh document (which owns its own destination tree) instead of the reverse.
- Auditing the 18 corrections previously living only as PDF-patch code (now removed, since those pages are source-rendered) turned up one still-real bug: two back-matter files (`99-to-spain.md`, `999-afterword.md`) quoted Romans 16:27 as "歸於獨一全智的神" where the verified CUV wording (already correct in chapter 16's own Scripture text, and what the patch it superseded had corrected to) is "歸與獨一全智的神" — fixed in source.
Verification beyond the standard suite: pages 1-228 confirmed byte/text-identical to the pre-splice PDF; zero LaTeX overfull-box/missing-character/undefined-control warnings across the fresh build; visual spot-checks on the cover, the new table, the Scripture-index appendix (links now render in link-color, confirming they resolve, vs. plain text before) and the back cover.

## Remaining release work

The [actual-PDF evidence](sources/audits/actual-pdf-evidence.json) records 815/866 normalized Scripture matches (433 English, 382 Chinese), originally reporting 51 Chinese differences. Of 198 detected quoted passages, 152 have normalized source-wording matches and 46 remain unresolved. Neither a mismatch nor a wording match alone decides accuracy, context, attribution, or permission.

**2026-09-21 verification (校對神 pass)**: the 51 flagged Chinese differences were checked verse-by-verse against cnbible.com's labeled "繁體中文和合本 (CUV Traditional)" column, per this project's standing Scripture-verification policy. Result: **`sources/reference/cuv1.json` (labeled "FHL和合本" but sourced from FHL's `unv` corpus) is not the plain CUV text — it matches the modernized 現代標點和合本 (CUVMP) on characteristic markers (那裡 vs 那裏, 嗎 vs 麼, 地 vs 的, 希臘 vs 希利尼, 哪 vs 那, leading full-width space before 神).** Of the 51 flagged verses, roughly 36 are this edition mismatch — the book's wording is correct CUV, and the reference corpus is wrong for this comparison. The remaining ~15 (across 2:5, 2:8, 7:6, 13:4, 13:10, 14:18, 15:7, 15:14, 15:27, 16:1, 16:15, 16:18, 16:27) were genuine deviations from CUV Traditional (忿/憤, 服事/服侍, 姊/姐, 於/與, 伸/申, 戒/誡, 分/份) and have been corrected in the chapter source files. This does not itself close the release gate — the PDF has not been rebuilt from the corrected sources, and cover/rights/accessibility work below is unaffected.

The 46 "unresolved" quotations are from a separate script, `scripts/audit_actual_pdf.py` (not `quote_audit.py`, whose `sources/quotation-evidence.json` registry is currently empty and untouched by this pass). `audit_actual_pdf.py` matches PDF-extracted quotes against locally cached source files in `sources/reference/`. Spot checks found three distinct causes behind the 46, not one:

- **False positives (not commentary at all)**: at least one flagged item is NASB's small-caps rendering of the OT-in-NT quotation at Romans 1:17 ("BUT THE RIGHTEOUS...") — Scripture text, not a commentator's quote — and at least two are hymn lines (Charlotte Elliott's "Just as I am"). These should not be in the denominator.
- **Confirmed tool false negatives**: at least two flagged quotes (Chrysostom's "whosoever you are that judgest...", Morgan's "the final word of the great letter...") are verbatim present in the already-cached `chrysostom-05.html` and `morgan.txt` respectively, yet were still marked unresolved. The cause was not fully diagnosed in this pass (the `fold()` normalization in `audit_actual_pdf.py` does not obviously explain it); this script's "unresolved" count cannot be trusted at face value without per-item review.
- **Genuine local-source gaps**: some quotes (e.g. Wesley's Aldersgate diary; Luther's *On Secular Authority*, distinct from the archived `luther-romans.html` preface) have no corresponding file under `sources/reference/` at all, so the script cannot resolve them regardless of correctness. Several of these were already checked by the earlier `verify-citations.py`/`verify-sermon-quotes.py` pipeline via a different method (0 drift, 0 missing, per `docs/scores/romans-2026-09-02.md`), which this newer script does not know about.

None of the 46 were confirmed as an actual wording error in this pass. Reconciling `audit_actual_pdf.py` against the older, already-verified evidence (rather than re-deriving it) remains open work.
