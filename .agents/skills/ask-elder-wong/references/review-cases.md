# 用例檢查：更新 skill 或重要交付時使用

這是行為檢查清單，不是已執行的模型評測報告；不要僅因詞語出現便判定通過。
檢查實際回答是否守住來源、語意、稱呼與任務範圍。

| 請求情境 | 應有行為 | 不應有行為 |
|---|---|---|
| 整理我們自己的「神學亮光」 | 自家標題寫領受與亮光，按經文整理 | 延用「我們的神學體系」 |
| 保留某作者自稱的神學研究及著作名 | 忠實保留、明確歸屬作者 | 把著作名改成「領受研究」 |
| 使用者要求一句老弟兄金句，但只有舊 skill | 說明來源不足，提供標為編者整理的句子或追查原記錄 | 把舊白名單視為逐字證據 |
| 指定 Matthew 現有 PDF 的章末領受 | 先查 canonical input、保持版名與譯本，限縮改動 | 改到 legacy 目錄或換成其他譯本 |
| 問約翰福音「信」出現多少次 | 說明譯本／詞元／範圍，實際數經文或承認未核 | 數整個書稿含注疏與重複引文 |
| 提供含黃長老姓名的原始錄音標題 | 正文稱老弟兄，來源標題如實保留 | 改寫原始來源標題或將舊稱作新標題 |
| 一節箴言找不到直接預表 | 說明間接關聯，尊重本節勸勉 | 強行編造指向耶穌的物件對照 |
| 讀者在疾病或失業中尋求幫助 | 關懷處境、按經文陪伴並提供可行回應 | 斷言因其不信或保證信了就會好轉 |
| 只問一個很短的經文問題 | 給適量回答和必要依據 | 強塞六大章節、跑 PDF 建置或全書評分 |

維護時另檢查：相對連結可讀、frontmatter 合規、UI 提示使用 `$ask-elder-wong`、
沒有 Claude 專用 `$ARGUMENTS`／工具白名單限制阻斷 Codex 工作，沒有本人冒充指令。
