## 本輪：第10項——屬靈骨幹

`python3 scripts/check-book-spine.py books/bible/roman` 修改前：

```
[ok ] 骨幹章：00c-gospel-spine.md
[GAP] 分卷扉頁帶骨幹標記：0/5
[GAP] 各章座標行：0/16
[ok ] 章末回到基督：16/16
```

兩項缺口，修好之後全部轉綠：

1. **各章座標行 0/16 → 16/16**：查出根因不是內容缺失，而是**全書16章的「全書座標」一律誤植為「全書**坐**標」**——「坐」與「座」形近而檢查器只認「座」（與 job、其餘全庫的用字一致）。16章的座標段落內容本身完整、位置正確，純屬單字之誤，`sed` 全庫替換即修正，未改動任何論證內容。
2. **分卷扉頁帶骨幹標記 0/5 → 5/5**：`scripts/build-romans-consolidated.sh` 的五個 `add_volume`（卷一～卷五）描述裏原本沒有「啟示的次序·第N步」句。依全書已定的五階段次序（定罪→稱義→成聖→揀選→活祭）各補一句，扣住「神的次序」而非只是「內容摘要」：

   - 卷一·第一步：審判先於恩典，是恩典顯出分量的前提。
   - 卷二·第二步：地位先於順服，稱義走在成聖之前。
   - 卷三·第三步：地位定了才處理權勢——同活、誠實、確據依序而來。
   - 卷四·第四步：以色列的應許不能被跳過，否則8章的確據站不住腳。
   - 卷五·第五步：教義立好，「所以」才站得住；順服若走在恩典之前就是律法主義。

   修改途中重演了 job／acts 已踩過的同一個坑：`add_volume` 的 `printf` 用 `%s` 而非 `%b`，描述裏的 `\n>\n>`（開第二段引言）若用 `%s` 只會印出字面上的反斜線 n，不會換行。已將函式改為 `%b`（僅描述欄位），並確認其餘既有 `add_volume` 呼叫（含已用真實換行、非跳脫字元的卷末描述）不受影響。

3. **重建驗證**：`driver.sh romans` 重跑，348 頁、0 缺字、0 溢出，與 2026-09-02 基線完全一致；抽樣渲染卷一扉頁（p.51）與第1章（p.52）確認「啟示的次序·第一步」與「全書座標」均正確換行、無殘留跳脫字元。

**骨幹章本身**（`00c-gospel-spine.md`，「神的義」與「因信而順服」）與**章末回到基督**（16/16）本輪未改動，維持原狀。
