## 1. Product Overview

### 1.1 Vision

一套能把聖經一卷一卷做成「出版級研讀書」的系統：經文準確、注疏可查、有一條帶讀者走的骨幹，而且讀者拿得到、讀得了、能帶小組用。

### 1.2 What the product actually is (2026-10)

| Layer | 內容 | 位置 |
|-------|------|------|
| 內容 | 每卷書的 markdown 章節、骨幹章、分卷扉頁、附錄 | `books/bible/<book>/` |
| 來源 | 經文與公有領域注疏原文（供機器核對） | `books/bible/<book>/sources/` |
| 建置 | pandoc + xelatex；每卷一支 build script、一個模板 | `scripts/build-*-consolidated.sh`、`templates/pdf/*.latex` |
| 驗證 | 骨幹、markup、經文用字、引文、講道、帳目檢查 | `scripts/check-*`、`lint-*`、`verify-*` |
| AI 工作流程 | eat-bible、ask-elder-wong、五個編輯 agent | `.claude/skills/`、`.claude/commands/` |
| 品質 | 十項評分表、成熟度階梯 | `docs/scores/` |
| 網站 | Next.js 首頁（約翰福音 MVP 佔位）、Firebase 儲存瀏覽頁 | `app/` |
| 靈修 | 每日筆記、週報、月報 | `daily-notes/`、`weekly-summaries/`、`monthly-reports/` |

## 2. User Personas

| ID | Persona | 背景 | 要的是甚麼 |
|----|---------|------|-----------|
| P1 | **作者／總編輯**（Jim） | 每天與 Claude Code 建卷、校對 | 少返工；同一個錯不犯兩次；知道每卷書到哪一步 |
| P2 | **個人讀者** | 有基本聖經知識的信徒 | 找到書、在手機或平板上讀、每天讀一段 |
| P3 | **小組帶領者／主日學老師** | 例：CCIC 哥林多後書課程 | 一課一份可印、可投影的材料；討論問題；時間配置 |
| P4 | **神學審核者** | 牧者或神學顧問 | 只看需要判斷的地方；能留下意見並追蹤是否已改 |
| P5 | **系統維護者**（Jim + AI） | 維護腳本、模板、網站 | 修一次全庫生效；有測試；CI 綠燈 |

## 3. User Stories

狀態：✅ 達成 · 🟡 部分 · 🔴 壞了 · ❌ 未做。評分（/10）依據見 `docs/system-evaluation-2026-10-31.md`。

### Epic A — 作者建卷 (P1)

| ID | User Story | Acceptance Criteria | 狀態 |
|----|------------|---------------------|------|
| US-1.1 | 作為作者，我要一個標準化的章節模板，讓每章都有系統地完成。 | 11 節模板；`lint-chapter-markup.py` 0 錯 | ✅ |
| US-1.2 | 作為作者，我要整合黃長老、MacArthur、Morgan 三方資源。 | 每章 ≥1 MacArthur 講道（有編號）、≥1 Morgan；「老弟兄查經」一節 | ✅（無 MacArthur 講道的書以公有領域注疏家補位，並在書中註明） |
| US-1.3 | 作為作者，我要中英經文對照。 | CUV + NASB 1995 並列，兩欄節數相同 | ✅ |
| US-A.4 | 作為作者，我要用一個指令建出任何一卷書，並知道它是否真的乾淨。 | `driver.sh <slug>`：0 缺字、0 溢出、與基準比對 | 🟡 可行；9 冊仍有溢出；撒母耳記下沒有基準 |
| US-A.5 | 作為作者，我要先知道一卷書有沒有骨幹，再決定下一步。 | `check-book-spine.py` 4/4 | 🟡 49 個目錄 4/4；巢狀目錄（保羅書信）與無 build script 的書檢查器看不到 |
| US-A.6 | 作為作者，我要一張書庫總表，一眼看出每卷在哪一階、還差甚麼。 | 自動產生；含頁數、溢出、骨幹、最新評分、是否已提交 | ❌ |
| US-A.7 | 作為作者，模板或建置腳本的 bug 修一次就全庫生效。 | 共用建置函式庫；各書只放設定與封面 | ❌ 104 支 build script、106 個模板各自複製 |

### Epic B — 準確與可查證 (P1, P4)

| ID | User Story | Acceptance Criteria | 狀態 |
|----|------------|---------------------|------|
| US-3.1 | 我要所有經文引文 100% 準確。 | 經文區塊、散文中加引號的經文、跨書引用全部雙來源核對 | 🟡 三種面都有檢查器；校對輪仍抓到轉述式引號與憑記憶的跨書引用 |
| US-2.1 | 我要看到歷代注疏，而且每一句都查得到。 | 引號內的句子能定位原文；帳目與書稿一致 | ✅ 各卷逐條核對；「注疏綜述」段落仍無機器檢查 |
| US-2.2 | 我要學習原文詞彙。 | 希臘文／希伯來文正確顯示、音譯、詞義、次數交代計法 | ✅ |
| US-2.3 | 作為帶領者，我要多元觀點。 | ≥3 位不同時代注疏家 | ✅ |
| US-B.5 | 我要一個指令跑完所有檢查，不靠記得順序。 | `check-all <slug>` 與 `--all`；非零即失敗 | ❌ 14 支腳本需逐一手動執行 |
| US-3.2 | 我要全書邏輯連貫、不自相矛盾。 | 前言、版權頁、評分表與書稿一致 | 🟡 靠 AI 通讀；過去多次抓到版權頁否認自己的聲明、兩處算錯同一範圍 |
| US-3.3 | 我要中英文表達自然。 | 無 AI 腔、無空洞套話 | 🟡 靠校對輪 |

## 4. Chapter Template (house standard, 取代 v3.0 §3.2.1)

```markdown
# 章題 (English)
## 基督焦點 (Christ at the Center)     鑰詞／座標 + 一段引子
## 配詩 (Opening Hymn)                 一節公有領域聖詩 + 中譯
## 經文 (Scripture)                    ### 中文 — 和合本 (CUV) / ### English — NASB
## 背景 (Context)
## 原文研讀 (Word Study)
## 領受要點 (Truths Received)          3–4 點，只屬於本章
## 歷代注疏 (Historical Commentary)    > 體例說明
## 詩篇與聖詩 (Psalm & Hymn)
## 老弟兄查經 (Reading with the Elder Brother)
## 生命應用 (Application)              ### 默想問題（≤3）/ ### 禱告回應
## 與其他經文的關聯
```

全文規格：`.claude/skills/eat-bible/references/chapter-template.md`。

## 5. Quality Gates (per book)

| 階 | 名稱 | 通過條件 | 工具 |
|----|------|----------|------|
| 1 | Build | 能建置、0 缺字 | `driver.sh` |

| 5 | Spine | 骨幹 4/4，讀者被帶到某處 | `check-book-spine.py` |
| 6 *(新)* | Reviewed | 牧者審核清單簽核 | 待建 |
| 7 *(新)* | Published | 有版本號、在書目頁可下載 | 待建 |

## 7. Open Questions

1. **發佈範圍**：書目頁要公開，還是只給教會內部（需登入）？
2. **閱讀形式**：手機閱讀先做 HTML 章節頁，還是 EPUB？（建議 HTML：可搜尋、可連結、與網站同一套）
3. **審核者**：誰擔任神學審核？從哪三卷開始？（建議：約翰福音、羅馬書、創世記）
4. **每日靈修**：要恢復「每日筆記＋週報」流程，還是改為「依書庫讀經計劃」？
5. **孫子兵法／資治通鑑**：仍在七年計劃中嗎？若是，另立 PRD。
